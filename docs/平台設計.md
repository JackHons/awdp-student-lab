# 中學生 AWDP 訓練平台設計

本設計面向準備參加 MOCSCTF 2026 的中學生與帶隊老師，使用繁體中文解釋概念，將找漏洞、提交 flag、修補程式和檢查結果串成一個可重複練習的流程。

官方 AWDP 名稱為 **Attack With Defense and Pwn**；已公布的比賽機制包括 15 分鐘輪次、flag 提交、修補檢查、防守得分、一血／二血／三血獎勵，以及同分按答題時間比較。資料來自 [MOCSCTF 2026 官方介紹](https://mocsctf2026.mocsctf.com/zh)。學生組每隊 2–4 名澳門中學生、每校最多 2 隊，並須參加賽前專業培訓，依據 [CAEP 章程](https://www.caep.edu.mo/latestNoticeDetail/129)。數值分數、精確排名算法、題型細分、部署方式及可用工具仍以主辦方完整規則為準。

官方知識域包括攻擊、防禦、Pwn、程式碼審計、服務維護、資訊收集及即時策略。本平台先以 Linux、HTTP、Python 與 Web／Pwn 入門承接這些能力，並非宣稱正式比賽只有兩種題型。CAEP 章程列 11 月 8 日 09:30–16:00，比賽網站列 10:00–16:00；資訊頁須並列時間差異並提示老師確認，不擅自把 09:30 寫成報到時間。

## 交付範圍與正式平台的界線

目前交付的是以純靜態 **HTML／CSS／JavaScript** 製作的**個人教學模擬原型**，不依賴 TypeScript 或後端 API。十個頁面提供 Linux 共同基礎、Web／Pwn／Defender 分流、patch 打包與提交及攻防演練；初學者可參考這個建議順序，所有訓練頁面均可直接使用。六道 CLI 文字自測、Linux 實作自評、20 項分流學習勾選及五項交付清單保留為個人進度。原有六個任務仍保留：HTTP、Base64、SQL、檔頭、Pwn 五個作答對話框，以及一個修補策略工作坊；另有四輪攻防模擬、四週學習清單與比賽資訊。它適合課堂示範與個人自學，沒有登入、隊伍帳號、共用排行榜或教師管理功能。

| 功能 | 教學原型 | 正式訓練平台 |
| --- | --- | --- |
| 帳號與隊伍 | 無登入或隊伍帳號；個人操作 | 伺服器驗證身份與隊伍權限 |
| Linux 建議基礎 | 六道 CLI 文字自測與實作自評記錄個人進度；分流、Defender、交付及攻防練習可直接使用，不受自測結果限制；不執行命令或驗證虛擬機 | 可配合老師審核實作證據；能力評估與存取權限分開處理 |
| 題目與 flag | 五個題目對話框及瀏覽器答案檢查；教學答案可被查看 | 由隔離靶場生成，伺服器驗證；不把有效答案放在前端 |
| patch | 選擇四種策略，比較三項預設檢查結果；不執行 SQL | 上傳實際修補產物，在隔離環境執行檢查 |
| 輪次與分數 | 四輪個人模擬；每輪 flag +100、修補且服務正常 +100，可用 60× 示範；數值非官方公式 | 伺服器時間、版本化規則、可稽核分數帳本 |
| 排行榜 | 無共用排行榜；僅本次個人的輪次結算及操作紀錄 | 多隊共用的伺服器排行榜與官方排序策略 |
| 學習進度 | 六道 CLI 通過紀錄、Linux 實作自評、20 項分流勾選、五項交付清單，以及原有任務、修補通過與 12 項四週清單，儲存在目前瀏覽器 | 可選擇儲存到個人帳號，與比賽分數分開 |
| patch 打包與提交 | 操作指南、命令文字範例及交付自評，沒有真實打包、上傳、SSH 或部署功能 | 由授權介面接收真實產物、驗證並執行隔離檢查 |

輪次歷史及倒數僅保存在目前頁面的記憶體，重新載入便會重置；上述學習紀錄、自評及清單使用瀏覽器 localStorage，清除資料後可能消失，不會同步到其他設備、老師或隊友，也不查詢 PortSwigger、picoCTF 等外部平台的完成狀態。輪次可暫停、恢復、提前結算或重新開始；真實時間為每輪 15 分鐘，60× 模式把一輪縮至約 15 秒，方便老師示範。

Linux 是建議的共同基礎，六道自測由前端答案比對記錄，實作由學生自行勾選；這些紀錄不限制任何訓練頁面的使用。直接進入課程不會新增通過紀錄或改變實作自評，既有學習進度仍予保留。平台沒有驗證命令是否執行、終端輸出或備份是否成功，老師可要求學生另交實作證據。分流勾選與交付清單亦不是已完成外部實驗、已上傳或 checker 通過的證明。前端原型的任何分數、倒數或「通過」結果都不構成正式比賽認證。正式平台不可相信瀏覽器提交的分數、時間、checker 結果或隊伍身份。

## 已交付的教學頁面

1. **備賽總覽**（`overview`）：展示 Linux → 分流 → patch 交付的建議順序、六道 CLI 自測、20 項分流及五項交付進度，提供可直接進入的課程、教材、報名與培訓入口。
2. **Linux 基礎**（`linux`）：先介紹 19 個不帶選項的命令，滑鼠／焦點／點按顯示詳細用法；接著講 owner/group/others 與 r/w/x，提供九位元權限計算器；最後下載 Python 生成器，在新目錄產生 50 個檔案及六種 flag 搜尋／解碼／權限任務。六道 CLI 文字自測與實作勾選記錄本課學習情況，學生亦可直接選擇其他訓練頁面。生成器不提權；root:root 600 檔案由 VM 中的獨立授權步驟設定，實際權限效果須在非 root Linux 帳號檢查。
3. **Web／Pwn／Defender**（`tracks`）：可直接選主修，Linux 作為建議基礎供學生按需要補練。保留共 20 項基礎勾選，另提供可按難度及中英文搜尋的 20 個 PortSwigger Web labs、12 個 Pwn 課程／實題／參考／題庫入口；清楚區分課程與單題。要求記錄根因、修補及檢查，勾選不查詢外部完成狀態。
4. **Defender 教學與 WAF**（`defender`）：11 個中英教學单元涵蓋備份、WAF、危險呼叫、PHP／反序列化、SQLi、SSTI、原型污染、上傳、Java 及審計。每項有四步教學、小練習、驗收目標與對應官方文件。另保留單欄位 WAF 比較及離線結構驗證練習，沒有真實代理或生產 WAF。
5. **Patch 打包與提交**（`delivery`）：可直接閱讀 staging、相對路徑、包清單、SHA-256、平台提交與條件式 SSH／SCP 指南，勾選備份、回歸、包內容、格式／hash、最終 checker／還原五項自評。沒有實際上傳、檔案封裝或遠端修改；官方格式、API 及驗證欄位仍須確認。
6. **靶場練習**（`challenges`）：可直接練習。六張題卡可按 Web／Misc／Pwn／Defense 篩選；五題在對話框內閱讀線索、開啟提示、輸入答案及查看正確解釋，第六題進入修補工作坊。原創教學任務不連接真實靶機。
7. **修補實驗**（`patch`）：可直接開啟並執行教學檢查。比較直接串接、封鎖單引號、參數化查詢和停止服務；三項預設檢查涵蓋普通姓名、含單引號的合法姓名與注入輸入，只有保留功能並阻止注入的策略通過本案例。
8. **輪次演練**（`round`）：可直接開始四輪個人練習，每輪重新提交教學 flag、套用曾通過工作坊的修補，觀察服務狀態對防守分的影響。顯示本輪預計分數、結算歷史及操作紀錄，沒有血獎、扣分或其他隊伍。
9. **備賽指南**（`guide`）：10 月 12 日至 11 月 8 日的四週路線與 12 項可勾選清單、2–4 人分工、15 分鐘建議節奏、賽日檢查及教師建議，可列印並下載 [完整備賽指南](./備賽指南.md)。頁面建議每週三次 45–60 分鐘；完整指南另提供團隊練習建議，可依課表調整。
10. **比賽資訊**（`competition`）：資格、正式報名途徑、必須參與的培訓、設備要求、官方來源、查詢方式及禁止行為；並列 CAEP 09:30 與比賽網站 10:00 的開始時間差異，提醒老師確認。

正式平台可在以上流程加入實際靶場、伺服器提交、patch 版本與非同步檢查、隊伍排行榜，以及分班、組隊、重置、重判和匯出的教師管理功能。這些均屬後續實作範圍。

所有重要狀態用文字配合顏色，鍵盤可完成操作；小螢幕可閱讀題卡與檢查結果。提示使用「輸入如何被處理」「哪段程式信任了資料」等問題引導學生。錯誤訊息提供下一步，不直接洩露未公開答案。

頁首提供中文／English 切換，保存在目前瀏覽器；切換會保留命令與姓名等輸入草稿，命令語法、URL 與 flag 內容不變。下載的實驗目錄內附中英文 README。教材與官方文件使用原文連結，切換不代表外部網站語言已改變。

## 正式平台架構

以下架構、資料表、API、驗證、隔離及維運設計是正式多隊平台的實作規劃，尚未包含在目前靜態教學原型中。

```text
學生／老師瀏覽器
       │ HTTPS
       ▼
Web 前端 ── API／身份驗證 ── PostgreSQL
                   │             ├─ 隊伍與權限
                   │             ├─ 提交、輪次與分數帳本
                   │             └─ 稽核事件
                   ├─ 佇列 ── Checker 工作節點 ── 隔離測試容器
                   ├─ 靶場控制器 ── 每隊／每題隔離實例
                   └─ 事件通知 ── 輪次狀態、檢查結果、排行榜

patch 產物 ── 私有物件儲存（雜湊、版本、期限）
```

正式前端可從現有純靜態 HTML／CSS／JavaScript 原型延伸，再按維護需要加入 TypeScript 或前端框架；API 可用 FastAPI 或同等框架；PostgreSQL 保存權威資料；Redis／任務佇列處理 checker；私有物件儲存保存 patch。先以一台受控主機與獨立靶場 VM 驗證流程，再按班級規模增設工作節點。技術選型是實作建議，不屬於官方規定。

管理 API、資料庫、物件儲存與 checker 工作節點不得出現在學生可攻擊的網絡。靶場 VM 是額外隔離邊界；容器用來限制資源與分開題目，不能視為唯一安全邊界。

## 核心資料模型

所有時間以伺服器 UTC 儲存，畫面可用澳門／香港時間顯示。ID 使用 UUID，提交及計分使用資料庫交易與唯一約束。

| 資料表 | 核心欄位與約束 |
| --- | --- |
| `users` | `id`, `display_name`, `role`, `auth_subject`, `active`；`role` 為 student／teacher／admin |
| `teams`, `team_members` | `team_id`, `user_id`, `class_id`, `school_id`；學生組驗證每隊 2–4 人及每校最多 2 隊，身份從 session 取得 |
| `events` | `id`, `name`, `mode`, `rules_version`, `status`；區分練習與正式活動 |
| `challenges` | `id`, `kind`, `difficulty`, `statement_version`, `artifact_hash`, `checker_version`, `allowed_targets` |
| `rounds` | `id`, `event_id`, `index`, `starts_at`, `ends_at`, `status`；15 分鐘由伺服器設定 |
| `instances` | `id`, `challenge_id`, `team_id`, `round_id`, `image_digest`, `state`, `endpoint`；目標歸屬方式按賽例設定 |
| `flag_tokens` | `id`, `instance_id`, `round_id`, `token_digest`, `expires_at`；不儲存可公開讀取的明文 flag |
| `flag_submissions` | `id`, `team_id`, `challenge_id`, `round_id`, `received_at`, `verdict`, `idempotency_key` |
| `patch_submissions` | `id`, `team_id`, `challenge_id`, `round_id`, `artifact_hash`, `checker_version`, `received_at`, `state` |
| `check_runs` | `patch_id`, `run_id`, `functional_verdict`, `security_verdict`, `resource_verdict`, `started_at`, `finished_at` |
| `score_events` | `id`, `team_id`, `round_id`, `challenge_id`, `source_id`, `category`, `points`, `rules_version`, `awarded_at`；同一來源不得重複得分 |
| `audit_events` | `actor_id`, `action`, `resource_id`, `request_id`, `created_at`, `detail`；記錄設定、重判、暫停和權限變更 |
| `learning_progress` | `user_id`, `lesson_id`, `completed_at`；與計分資料分開，無須以學習勾選判定得分 |

題目實例可以是每隊獨立副本，或規則明確授權的共享／對手目標。MOCSCTF 的具體目標拓撲未在此假定，正式部署須先按主辦方規則確定 `allowed_targets`；預設教學環境只允許隊伍自己的隔離副本。

## API 草案

前端提交請求使用 session 權限、CSRF 防護與請求大小限制。`team_id` 等歸屬欄位以伺服器 session 決定，學生不能藉請求指定其他隊伍。

| 端點 | 用途 |
| --- | --- |
| `GET /api/me` | 使用者角色、隊伍、可參與活動 |
| `GET /api/events/{id}/state` | 伺服器時間、輪次、期限、規則版本、允許操作 |
| `GET /api/challenges` | 經授權題目清單與學習資訊 |
| `GET /api/challenges/{id}` | 題目版本、靶場端點、允許目標與提交限制 |
| `POST /api/flag-submissions` | `{challenge_id, round_id, flag, idempotency_key}`；返回提交 ID、接收時間與判定 |
| `POST /api/patch-submissions` | 已驗證的 patch 產物及題目／輪次；返回提交 ID 與 `queued` |
| `GET /api/patch-submissions/{id}` | 僅本隊與有權老師可讀；返回狀態及可公開的檢查摘要 |
| `GET /api/events/{id}/scoreboard` | 伺服器計算的總分、分類分數、排序、規則版本與快照時間 |
| `GET /api/events/{id}/stream` | SSE 通知輪次、檢查及榜單更新；斷線後重新抓取權威狀態 |
| `PUT /api/learning-progress/{lesson_id}` | 保存個人學習進度；不影響分數 |
| `POST /api/teacher/events/{id}/pause` | 具權限老師暫停活動，附原因並記錄稽核 |
| `POST /api/teacher/instances/{id}/reset` | 重置指定靶場，按活動規則保留提交紀錄 |

建議狀態碼：未登入 `401`、無權限 `403`、格式問題 `422`、輪次已關閉／版本衝突 `409`、速率限制 `429`。成功接收不等於通過；前端須繼續讀取提交狀態。

## 伺服器驗證與計分

1. 驗證 session、隊伍、題目權限、允許目標、提交輪次與伺服器期限。伺服器以接收時間決定是否在期限內，不能使用客戶端時鐘。
2. flag 帶有不可猜測的值，綁定題目／實例／輪次與期限。比對雜湊或驗證簽章；同一已認可成果用唯一約束去重；前端只能取得判定。
3. patch 進入佇列，保存產物雜湊與 checker 版本。每次檢查在乾淨副本上重建，再跑正常功能、漏洞案例和資源限制檢查。
4. 通過後由計分器寫入 `score_events`；符合血獎條件的解題事件，在同一交易中鎖定完成排名並分配一血／二血／三血獎勵，避免同時提交獲得不一致名次。哪些事件適用獎勵由官方規則設定，不能預設所有 patch 都有血獎。
5. 排行榜從帳本聚合；重判以追加調整事件處理，保留原始紀錄。學生頁面顯示分數來源與規則版本。

官方未公布的數值全部存入版本化規則設定，包含攻擊分、防守分、獎勵及同分時間比較方式。在取得完整賽例前，不把自行推定的係數或「最後一次提交時間」當作官方排名算法。教學模擬的公式必須直接標示為示例，且與正式規則分開。服務異常確定不符合成功修補；官網服務維護說明稱會扣分，規則正文則稱沒有防守得分，扣分幅度和適用情境需確認後才能配置。

輪次採用明確狀態 `scheduled → active → closed → finalized`。跨輪 flag、接近截止的 patch、checker 超時及重試是否計分，都需活動規則明文設定。基準流程以按時接收的提交進入檢查，結算後生成可稽核快照；採用其他方式前需先公布。

## 靶場與 patch 檢查的隔離

- 靶場及 checker 置於獨立 VM／工作節點，與平台控制面分網；每題使用獨立容器、非 root 使用者、唯讀基底映像及可重置資料卷。
- 容器移除 capabilities、啟用 seccomp／同等系統呼叫限制，禁止 privileged 模式、主機目錄掛載與 Docker socket；限制 CPU、記憶體、程序數、磁碟及執行時間。
- 靶場 VM 預設禁止對外連線，拒絕存取平台資料庫、管理網段、雲端 metadata 及其他未授權實例；必要套件預先放入映像。
- 只開放題目需要的連接埠，經閘道映射給獲授權隊伍；依 `allowed_targets` 確定能存取哪些實例。
- patch 限制格式、大小、檔案數和路徑，拒絕路徑穿越、符號連結及主機寫入；使用專用工作容器套用及執行，絕不在 API 主機直接執行學生程式。
- 正常與安全檢查均需通過；封鎖全部請求、移除題目功能或輸出偽造通過文字不能得防守分。
- 檢查日誌只公開必要摘要；完整診斷由老師讀取，避免未公開 checker、其他隊伍資料或有效 flag 流入學生頁面。

每個實例可一鍵銷毀並由固定映像重建。教師可暫停題目或整場活動，將該操作、受影響輪次和結算決定保存到稽核紀錄。

## 身份、資料與維運

使用學校／活動核發帳號，收集最低限度的暱稱、班級及隊伍資料；不需要學生在靶場輸入真實身份資料。密碼採可靠雜湊；管理者可使用多因素登入。使用 HTTPS、Secure／HttpOnly session Cookie，權限檢查覆蓋所有 API、檔案下載和事件通知。

監測 API 錯誤、佇列長度、checker 超時、靶場資源與計分延遲；為學生展示簡短平台狀態。資料庫和產物儲存定時備份，演練還原後再使用正式活動。活動前做權限、輪次邊界、重複提交、同時提交、重判及故障復原測試。

活動結束後依學校與主辦方的資料保留政策匯出隊伍結果，再刪除不需保留的提交產物與個人資料；政策須在帳號啟用前向師生說明。

## 分階段實作與驗收

| 階段 | 交付 | 驗收重點 |
| --- | --- | --- |
| 1. 教學原型（已交付） | 純靜態頁面、五個作答對話框及修補工作坊、四輪個人模擬、四週本地清單、官方資訊 | 每個模擬功能有清楚標示；沒有帳號或共用排行榜；明確區分本地保存的進度與刷新即重置的輪次 |
| 2. 單班訓練 | 身份、組隊、題目 API、獨立靶場、flag 提交、patch 佇列、教師查看 | 至少兩隊不能讀取彼此私有資料；正常與漏洞檢查都有效；重複提交不重複得分 |
| 3. 多隊輪次 | 伺服器輪次、分數帳本、血獎交易、排行榜、活動暫停及重判 | 同時提交排序一致；跨輪及過期輸入按規則判定；客戶端修改分數無效 |
| 4. 活動部署 | 完整隔離、稽核、備份、監測、負載及還原演練 | 靶場無法連到控制面及外網；服務故障可按公布流程處理；完整賽例已確認 |

正式啟用前須完成四項具體核對：學生資格與 2–4 人／每校最多 2 隊要求、可攻擊目標與工具、完整計分及同分規則、patch 格式與 checker 時限。這些設定不能從教學原型自動繼承。
