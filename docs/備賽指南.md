# 中學生 AWDP 四週備賽指南

建議的學習路線是 **Linux CLI 共同基礎 → Web／Pwn／Defender 分流 → patch 打包、提交與回歸檢查**。Linux 是初學者的建議基礎；所有訓練頁面都可直接使用，學生可按已有能力與主修需要選擇順序。四週計畫建議第一週練 CLI，後三週依主修練習並定期交換角色。CLI 自測、實作自評及分流清單仍如實保留為個人學習紀錄，直接進入課程不會自動通過自測；老師以終端操作、解題筆記及修補檢查驗收。

- [Linux CLI 入門與六項自測](./Linux-CLI入門.md)：參考 ICOA Starter，加入 AWDP 備份及提交所需命令。
- [Web 與 Pwn 路線](./Web與Pwn練習路線.md)：PortSwigger 入門實驗、picoCTF 教材、堆疊溢位及格式化字串。
- [Defender 修補速查與 WAF](./Defender修補速查.md)：PHP、SQL 注入、SSTI、原型鏈污染、上傳、Java、審計及復原。
- [Patch 打包與提交](./Patch打包與提交.md)：封裝、清單、SHA-256、上傳方式、checker 結果及還原。

適用對象：準備參加 MOCSCTF 2026 的澳門中學生，以及帶隊老師。學生組每隊 **2–4 人**，每校最多 **2 隊**，且必須參與賽前專業培訓。即使未接觸過 CTF，也可以從第一週開始。本文把官方賽程轉成學習安排；練習題、角色分工和教學計分均為本平台設計，並非主辦方公布的完整賽例。[學生組章程](https://www.caep.edu.mo/latestNoticeDetail/129)

## 先了解比賽

AWDP 的官方名稱為 **Attack With Defense and Pwn**。參賽者需要找出題目漏洞、取得並提交 flag（用來證明完成題目的特定字串），也需要修補程式，讓修補版本通過檢查。這不是單靠背工具指令的比賽：正常功能是否仍能使用，同樣重要。

| 已公布項目 | 備賽時要怎樣做 |
| --- | --- |
| 每輪 15 分鐘 | 練習把閱讀、驗證、修補、提交拆成短步驟，預留時間重測 |
| 攻擊以提交 flag 作答 | 記錄取得 flag 的題目與輪次；留意提交後的確認結果 |
| 修補通過檢查可獲防守分數 | 每次修補都測正常功能及漏洞案例，不能只令程式停止運作 |
| 一血、二血、三血有額外分數 | 在正確性穩定後練習速度；獎勵數值及適用細節依主辦方規則 |
| 同分時以答題時間比較 | 每輪盡早提交已驗證的成果，保留伺服器確認紀錄 |

以上依據：[MOCSCTF 2026 官方比賽介紹](https://mocsctf2026.mocsctf.com/zh)。服務異常不符合成功修補；官網服務維護說明提到扣分，規則正文則寫沒有防守得分，扣分幅度與適用情境須向主辦方確認。可用工具、題型細分、各項分數、提交次數與裁判檢查細節，以主辦方最新公告為準。

## 練習環境與分工

每週建議完成三次 45–60 分鐘小練習，以及一次 75–90 分鐘團隊練習。先把每一步做懂，再縮短時間。只有本平台、老師指定的隔離環境或主辦方明確授權的比賽目標可以練習；不要對學校系統、同學設備或公開網站測試漏洞。

學生須自備可安裝虛擬機、連接 Wi-Fi 或本地網絡的手提電腦；CAEP 最低建議配置為 **4 核心 CPU、8GB 記憶體、50GB 可用儲存空間**。老師可協助準備 Linux 虛擬機、Python、文字編輯器及瀏覽器開發者工具，讓學生保存筆記和修補檔；安裝前先備份，建立可還原快照。具體工具版本及比賽允許範圍須依主辦方公告。不要把個人密碼、真實學生資料或學校憑證放入靶場。[設備要求](https://www.caep.edu.mo/latestNoticeDetail/129)

每隊 2–4 人，按工作分配角色；2 人隊合併分析與攻擊、防守與紀錄，3–4 人隊可再分出計時及協調工作：

| 工作 | 主要責任 | 人數較少時 |
| --- | --- | --- |
| 題目分析 | 閱讀題目、找入口、整理可重現步驟 | 與攻擊驗證合併 |
| 攻擊驗證 | 在授權目標驗證漏洞、提交 flag | 由分析者兼任 |
| 修補及回歸 | 找根因、修改程式、測正常功能及攻擊案例 | 每人負責自己分析的題目 |
| 時間及紀錄 | 提醒剩餘時間、核對輪次、保存提交結果 | 由輪值同學兼任 |

每次練習交換角色，避免只有一人懂得操作。提交前用一句話互相交代：「我改了甚麼、正常功能如何驗證、漏洞如何重測。」

## 第一週：10 月 12–18 日——看懂系統與請求

目標：能在 Linux 找到檔案、閱讀程式，並用自己的話解釋一個 HTTP 請求。

1. Linux：練習 `pwd`、`ls`、`cd`、`cat`、`less`、`mkdir`、`cp`；認識路徑、權限、程式輸出及錯誤訊息。只在練習資料夾操作。
2. HTTP：在瀏覽器開發者工具觀察請求方法、網址、參數、狀態碼、Cookie 與回應內容。把「畫面上的按鈕」連到「送往伺服器的資料」。
3. Python：寫一個讀取練習文字檔、檢查輸入長度及輸出結果的小程式；讀懂變數、條件、迴圈、函式及例外。
4. 團隊練習：一人示範正常請求，另一人解釋輸入從哪裏來、由哪段程式處理，再共同記錄測試結果。

完成標準：不用複製整段教學也能找到指定檔案；能指出 HTTP 的輸入與輸出；遇到錯誤時先讀訊息，再作修改。老師在 10 月 22 日截止前完成報名確認。

## 第二週：10 月 19–25 日——從漏洞到修補

目標：理解「漏洞原因 → 最小驗證 → 修補 → 回歸測試」的完整流程。

1. Web（網頁）練習：分辨使用者輸入與可信資料；認識 SQL 參數化查詢、伺服器端權限檢查及輸出編碼的用途。不要用「看到某個關鍵字就封鎖」代替根本修補。
2. Pwn（程式漏洞）入門：認識程式輸入、緩衝區、長度限制及崩潰；閱讀老師提供的簡短 C 程式，指出「輸入比空間大」會造成甚麼問題。先掌握安全處理與除錯概念。
3. 完成下方 SQL 修補練習，把每個檢查的預期和實際結果寫下來。
4. 團隊練習：由另一位同學根據筆記重做驗證，確認步驟足夠清楚。

官方知識域包括攻擊、防禦、Pwn、程式碼審計、服務維護、資訊收集及即時策略。本平台以 Web 與 Pwn 入門練習承接這些能力；閱讀程式找根因就是程式碼審計，查看指定服務的請求及日誌屬資訊收集，保存快照和恢復正常功能屬服務維護。正式題目細分與難度仍須依主辦方公告。初學者可以先完成 Web 工作流程，再由老師帶領閱讀 Pwn 題目。[官方介紹](https://mocsctf2026.mocsctf.com/zh)

完成標準：能說明漏洞根因；修補後正常功能成功、攻擊案例不再改變查詢邏輯；筆記可由隊友重現。

## 第三週：10 月 26 日至 11 月 1 日——練習 15 分鐘輪次

目標：在時間限制內完成一次可重現、可提交、可檢查的成果。

| 輪次時間 | 建議動作 |
| --- | --- |
| 0–3 分鐘 | 讀題、確認授權目標與輪次、測一次正常功能 |
| 3–7 分鐘 | 重現漏洞並保存證據；取得 flag 後立即核對及提交 |
| 7–11 分鐘 | 修補根因，避免大幅重寫 |
| 11–13 分鐘 | 跑正常與漏洞案例；通過後提交修補版本 |
| 13–15 分鐘 | 看伺服器確認、保存紀錄、交代未解問題 |

這是練習節奏，不是官方指定作答順序。若一個假設連續無進展，先寫下卡點，讓隊友接手或換題。不要為追求速度省略正常功能檢查。

10 月 30 日至 11 月 1 日參加官方培訓時，重點確認：flag 如何提交、patch 如何上傳、檢查狀態如何閱讀、哪些操作獲授權。將主辦方解答加入隊伍筆記。

完成標準：至少完成兩輪模擬；每輪留有題目、版本、提交狀態與時間紀錄；隊員都能讀懂檢查失敗的原因。

## 第四週：11 月 2–8 日——正式流程演練與比賽準備

目標：熟悉實際平台，讓比賽當天的操作穩定。

1. 11 月 2–5 日在官方練習平台測試登入、找題、提交 flag、提交 patch 及閱讀檢查結果。依平台提供的能力進行，不假定所有本地模擬功能都存在。
2. 做一次連續四輪的團隊演練，每輪 15 分鐘；輪間只用簡短紀錄交換資訊。
3. 11 月 6 日整理常用筆記、測試案例與環境；停止添加尚未理解的新工具。
4. 11 月 7 日由老師核對交通、報到、設備、電源及文件；學生安排休息。
5. 11 月 8 日先完成設備與帳號檢查，按主辦方安排比賽；以伺服器回報為提交成功的依據。

完成標準：每位隊員都能登入及完成一次正式練習提交；遇到檢查失敗時能找回提交版本；熟悉求助及裁判聯絡方式。

## 範例：在授權的本地環境修補 SQL 查詢

題目情境：一個只含虛構資料的使用者搜尋頁。正常搜尋 `alice` 應只回傳 Alice 的公開資料。原始程式把輸入直接拼入 SQL，導致輸入可能被當作查詢語法。老師提供隔離副本，學生只測試這個副本。

修補方向：使用資料庫驅動的參數化查詢，令輸入被當成資料；只回傳需要的公開欄位；錯誤回應不要包含 SQL、路徑或堆疊。以下為 Python `sqlite3` 的安全查詢片段，`conn` 由題目程式提供，並非完整網站：

```python
def find_public_profile(conn, username):
    if not isinstance(username, str) or not 1 <= len(username) <= 64:
        raise ValueError("搜尋名稱長度不正確")
    return conn.execute(
        "SELECT username, display_name FROM profiles WHERE username = ?",
        (username,),
    ).fetchall()
```

不要用字串插值、字串串接或自行加引號代替參數。長度檢查用來限制輸入量，真正阻止輸入變成 SQL 語法的是參數化查詢。

建立只有 `alice`、`bob` 及 `O'Neil` 三個虛構帳號的測試資料後，先寫預期結果，再執行檢查：

| 類別 | 輸入或動作 | 修補後預期 |
| --- | --- | --- |
| 正常功能 | 搜尋 `alice` | 只回傳 Alice 的公開資料 |
| 正常功能 | 搜尋 `bob` | 只回傳 Bob 的公開資料 |
| 正常功能 | 搜尋 `O'Neil` | 可搜尋含單引號的合法名稱 |
| 正常功能 | 搜尋不存在的 `carol` | 空結果或清楚的「找不到」提示 |
| 漏洞案例 | 搜尋 `' OR 1=1 --` | 被當作完整搜尋字串，不會回傳全部帳號 |
| 邊界案例 | 空字串、超過 64 字元、非文字 | 按約定回報輸入錯誤，服務仍可使用 |
| 回歸檢查 | 漏洞案例後再次搜尋 `alice` | 正常功能仍成功，資料未被改動 |

「找不到結果」不等於所有 SQL 輸入都必須被封鎖。修補應讓任何文字都不會改變 SQL 結構，同時保留合法名字的搜尋功能。老師可加入未公開案例，檢查學生是否修補根因。

本平台的 SQL 練習是瀏覽器內的教學模擬，用來比較修補前後的預期結果；它沒有實際 SQL 伺服器，也不能證明真實程式已安全。正式 patch 必須在隔離環境由伺服器執行檢查。

## 每輪紀錄與檢查清單

建議每題用一張短紀錄：`題目 / 輪次 / 授權目標 / 漏洞根因 / 驗證步驟 / flag 提交結果 / patch 版本 / 正常檢查 / 漏洞檢查 / 待辦`。不要在共享筆記公開仍有效的 flag、個人密碼或其他隊伍資料。

提交前：

- [ ] 目標、題目與輪次正確，操作在授權範圍內。
- [ ] 取得的 flag 已完整複製，提交後有成功或失敗回報。
- [ ] patch 修補了根因，未破壞正常功能。
- [ ] 正常、漏洞及邊界案例都已重測。
- [ ] patch 版本及檢查結果已保存，隊友知道目前狀態。

比賽前：

- [ ] 老師確認報名、資格及官方最新規則。
- [ ] 每人能登入平台，帳號問題已提早處理。
- [ ] 手提電腦可運行虛擬機及連接 Wi-Fi／本地網絡，已備份並留有足夠空間；充電器及文件已備妥。
- [ ] 必須參與的官方培訓已排入日曆，比賽開始時間差異已向學校或主辦方確認。
- [ ] 只帶規則允許的工具與資料，知道如何向裁判求助。
- [ ] 隊伍完成一次限時演練，並安排休息與輪值。

## 帶隊老師的支援方式

老師先示範一題的完整流程，再讓學生自行提出假設；提示可由「資料從哪裏進入」逐步加深到「哪個 API 能讓輸入成為資料」。每週用可重現步驟、修補解釋及檢查紀錄評估進步，而不是只看得分。

使用隔離且可重置的靶場；練習帳號只含虛構資料；限定目標及網絡範圍；平台出現異常時先停止該題、保存紀錄，再由老師處理。若學生發現授權範圍外的問題，停止測試並向老師報告。

官方禁止攻擊比賽平台、改動排行榜、造成過載或阻斷服務；只可操作指定伺服器／服務。禁止社交工程、分享／索取／刪除旗幟、妨礙他隊提交及賽結束前外傳題目內容；每隊只登記一個隊伍帳號，不分享帳號密碼。練習時就遵守同樣的範圍，提交及測試紀錄只供本隊與有權老師查看。[官方規則](https://mocsctf2026.mocsctf.com/zh)
